# Phase 2 — 非AIバックテスト仕様 v1

この実装は日本株・日足・現物買い・無借入の研究用シミュレーション。
実売買への接続はない。既存のObservation、as_of、品質検査、ハッシュ保存を再利用する。

## データと実行順序

設定の `sessions` は事前に固定した営業日の昇順リスト、`universe` はsource付きentity_id。
実際の営業日や過去の上場銘柄を自動推定しない。売買単位は全銘柄共通の `lot_size`（既定100株）。
対象市場・頻度・注文方式は変更不可。設定外のフィールドは拒否する。

各営業日の日本時間18時をPIT切断点とし、以下を順に実行する。

1. `available_at < 18時` の日足を選択。observedではさらに `ingested_at < 18時`。
   historicalは根拠付きavailabilityと固定knowledge_atが必要。estimatedは採用しない。
2. 前営業日以前の注文を、その日の未調整終値にスリッページを加減して模擬約定。
   日足は終了後に確認するシミュレーター入力であり、当日の判断はまだ行わない。
   現実の引け注文の保証や取引所の約定再現を意味しない。
3. 現金と保有数量を更新し、当日の終値で評価。
4. ISO週の最初の設定営業日（祝日週は次の営業日）の18時に、PIT履歴から目標数量を決めて注文する。
   その日の終値では約定しない。期間初日が週途中なら初日が最初の判断日になる。

売却を先に処理し、その資金を購入に利用する。各方向内は銘柄ID順に固定。
翌日の価格は注文数量決定に使わない。価格上昇時は手数料込みで買える単位数まで縮小し、
残りを取消（partial_cancelled）。最低単位を買えなければrejected。借入・空売りは行わない。
これは資金上限付きの模擬執行であり、実注文の証拠金・拘束金管理とは異なる。

当日の日足が18時までに利用できない、価格欠損、出来高ゼロなら約定を延期。
次の週次判断時に未約定注文を取消し、新しい目標へ置換する。
最終日の未約定注文はpendingのまま保存し、強制決済しない。
欠損した保有価格は最後に観測した価格で暫定評価し、`stale_marks`に記録する。
当日価格がない対象銘柄は `unavailable_symbols` に記録する。欠損を正常な評価と混同しない。

## 戦略

- `buy_and_hold`: 初めて価格を参照できる週次判断で、利用可能な対象銘柄へ等金額配分。
  一度だけ発注し、以後の買い増し・リバランス・注文更新はしない。未約定は後続日に持ち越す。
- `equal_weight`: 毎週、当日価格のある対象銘柄に等金額配分。対象外となった保有分は売却対象。
- `momentum`: 設定営業日で直近lookback区間の終値リターンを計算し、正の上位top_n銘柄へ等金額配分。
  同点は銘柄ID順。必要なlookback+1本に欠損がある銘柄は除外。正の銘柄がなければ現金。
  期間内で履歴を蓄積するため、初期lookback営業日はウォームアップ。期間前の価格は戦略に使わない。

目標株数は売買単位で切り捨てる。手数料・端数・価格変化・ID順の資金配分により、約定後の比率は厳密な等金額ではない。

## コストと台帳

金額は精度28桁の固定Decimalコンテキスト。設定・保存上の金額は文字列。
買値 = 終値 × (1 + slippage_bps / 10000)、売値 = 終値 × (1 − slippage_bps / 10000)。
手数料は各約定の金額 × commission_bps / 10000 + commission_fixed。
約定がない注文に課金しない。円単位の丸めや税金は扱わない。
売却代金が手数料を下回る場合は売却を拒否する。

結果は注文（状態・判断日・数量）、約定兼売買履歴（基準価格・約定価格・数量・コスト・約定後現金）、
日次スナップショット（現金・保有数量・評価価格・資産評価額）、指標を含む。
台帳から現金 = 初期現金 − 購入代金 + 売却代金 − 全手数料を再計算できる。
最終損益 = 再計算した現金 + 最終保有数量 × 最終評価価格 − 初期現金。
スリッページは約定価格に含まれるので二重に引かない。未実現損益を含み、配当は含まない。

## 指標定義

すべてコスト反映後の評価額。年率換算営業日数252、無リスク利子率0。

| 指標 | 定義 |
|---|---|
| 累積リターン | 最終評価額 / 初期現金 − 1 |
| CAGR | (最終評価額 / 初期現金)^(365.25 / 最初から最後までの暦日数) − 1。1日だけならnull |
| 最大ドローダウン | 初期現金を含む過去最高評価額からの最大下落率（正数） |
| 年率ボラティリティ | 日次単純リターンの標本標準偏差 × √252 |
| Sharpe ratio | 日次平均リターン / 標本標準偏差 × √252。標準偏差ゼロならnull |
| 売買回転率 | 全購入・売却約定金額の合計 / 日次平均評価額。片道換算・年率化はしない |

日次リターンは初期現金から最初の日次評価へのゼロリターンも含める。1標本のボラティリティは0。
短期fixtureの年率指標は実装検証用であり、運用成績の証拠ではない。

## オフライン実行と再現

```sh
PYTHONPATH=src python3 - <<'PY'
import json
from pathlib import Path
from ai_trading.backtest import BacktestConfig, save_experiment, replay_experiment
from ai_trading.providers import normalize_daily
fixture = json.loads(Path('tests/fixtures/backtest_pages.json').read_text())
rows = normalize_daily(fixture['pages'], source='fixture')
config = BacktestConfig(**json.loads(Path('config/backtest.json').read_text()))
manifest = save_experiment(rows, config, Path('experiments/backtests'))
print(manifest)
print(replay_experiment(manifest)['metrics'])
PY
```

既存のハッシュ付きprocessed JSONLにも接続できる（設定のuniverseを入力のentity_idに合わせる）。

```sh
PYTHONPATH=src python3 -m ai_trading.backtest --config config/backtest.json --data data/processed/<hash>.jsonl --output experiments/backtests
```

`inputs/`に全入力Observation、`results/`に結果、`manifests/`に設定・入力ハッシュ・結果ハッシュ・
コードハッシュ・Pythonバージョン・執行仕様IDを内容アドレス付きで保存する。
replay_experimentは改変と環境差を検査して再実行し、結果バイト列を照合する。
入力順は結果に影響しない。同じデータ・設定・コード・Python環境で同じ成果物になる。
未来データを追加すると入力ハッシュは変わるが、過去期間の売買・評価は変わらない。

## 残る制約とPhase 3の前提

- 実際の銘柄履歴、上場廃止、公式営業日、売買単位変更、データ配信時刻の根拠を整備する。
  固定universeによる生存者バイアスを解消するまでは実市場での有効性を主張しない。
- 分割・併合等のadjustment_factorが1以外、または不明なら停止する。配当・企業イベントのキャッシュフローは未実装。
  factor=1だけで企業イベントの網羅性は保証できない。
- 値幅制限、板、売買停止の分類、出来高参加率、市場インパクト、決済日・資金拘束、銘柄別売買単位を整備する。
- 欠損・stale評価の許容基準とカバレッジ合格基準を定義する。全現金の結果も「データが十分」の意味ではない。
- PITスナップショットを日ごとに全走査する実装。長期・多数銘柄には索引化が必要。
- Phase 3でモデルを導入する前に、評価期間・ホールドアウト・ウォークフォワード・比較コストを固定し、
  この3基準戦略の同一データ上での比較結果を保存する。実装済みのfixture検証と経済的な有効性検証を分ける。

機械学習、LLM、ニュース分析、実売買APIは実装していない。
