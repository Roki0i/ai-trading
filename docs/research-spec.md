# 研究仕様 v1 — Phase 0

採用日: 2026-09-14。目的は当時利用可能だった情報だけによる、再現可能な投資仮説検証。
AIの予測能力や利益を前提にしない。現段階の成果物はデータ基盤であり、投資成績ではない。

## 固定する研究条件

| 項目 | 決定 |
|---|---|
| 市場 | 日本株 |
| 頻度 | 日足 |
| ポジション | 現物買いのみ。空売り・信用取引なし |
| リバランス | 週次 |
| レバレッジ | なし。総投資額は自己資金以下（設定値1） |
| 市場タイムゾーン | Asia/Tokyo。保存・比較する時刻はUTC |
| 判断・執行 | 将来の検証では必要データの利用可能時刻後に判断し、その後の取引機会で執行 |
| 実売買 | 実装・実行しない |

これらは `config/research.json` と設定バリデータでも固定する。研究条件の変更には新しい仕様版と設定版を必要とする。
Phase 2の週次判断時刻・祝日週・約定・現金計算は[非AIバックテスト仕様 v1](backtest.md)で確定。
以下のPhase 0–1範囲は当初の記録であり、Phase 2で基準戦略とバックテストを追加した。

## Phase 0–1 の実装範囲

- 設定、原本保存、正規化、point-in-time参照、品質検査、オフライン再生。
- J-Quants v2の日足取得アダプタ。デフォルトは架空データのfixture。
- HTTP通信、ページング、異常系をAPIキーなしのmockで検証。
- 予測モデル、LLM、特徴量、シグナル、ポートフォリオ、バックテスト、発注は対象外。

## まだ結果を見る前に決める事項

対象期間・学習評価区間、銘柄選定と最低履歴、投資資金、銘柄数、コスト、流動性制約、比較対象をPhase 2開始前に固定する。
今回の `dataset.date` は取得対象日の例であり、研究期間を意味しない。
当時の銘柄マスター・上場廃止・営業日・企業イベントの履歴カバレッジを確認するまで、日足取得成功を「バックテスト可能」と判断しない。

## 合格条件

1. APIキー・追加の実行時依存ライブラリなしでfixtureを取り込める。
2. 原本、設定、実装のハッシュから正規化データと品質レポートを再生成できる。
3. 公表前・取得前・訂正前の参照と、未来データ追加の不変性を検査できる。
4. 品質エラーがあるデータはprocessedとして公開しない。
5. 取得不能・不明な時刻・カバレッジ不足を成功した事実と区別する。

収益が出ることは、この段階の合格条件に含めない。
